# Architecture, implementation, and delivery audit — 2026-08-04

This document separates observations verified against commit `22a60bc66a62afc821e686eeaeb8119b99a51a40` from
recommendations and their implementation status. Counts describe the pre-refactor tree unless explicitly marked
current. The audit did not create, modify, probe, or delete any Hetzner Cloud resource.

## Scope and method

The audit inspected all tracked source, authored and generated documentation, tests, configuration, automation,
release metadata, Git history and GitHub remote metadata. Baseline verification used Go 1.26.5, golangci-lint 2.12.2,
`go test`, the race detector, `go vet`, `go mod tidy`, `go fix`, `govulncheck`, actionlint and GoReleaser validation.

A structural knowledge-graph pass classified 874 files (561 code, 276 documentation, 28 configuration, 6
infrastructure and 3 scripts) into 1,800 nodes and 21,706 dependency edges. It found these layers:

| Shared command framework | 19 |

The graph found no structural dependency violation. Its 72 standalone/orphan warnings were expected leaf files,
fixtures, generated pages, or automation entry points rather than unreachable production code.

## Verified baseline

### Repository and delivery status

- The canonical remote is `https://github.com/hetznercloud/cli.git`; the working fork is
  `https://github.com/krowd3v/cli.git`.
- At the audit snapshot, the canonical repository exposed 19 open issues and 8 open pull requests. The audit checked
  those PRs for overlap; the API-command and token-shell work were deliberately left untouched.
- The authenticated account had read access to the canonical repository and administrative access to the fork. It
  therefore could not merge a canonical PR without a maintainer action.
- All existing third-party GitHub Actions were already pinned to full commit SHAs. Workflow permissions, timeouts and
  concurrency policy were inconsistent, and the release lacked SBOMs and provenance attestations.
- Baseline unit, race, formatting, vet, module, lint and build checks passed. `govulncheck` found no reachable known
  vulnerability.

### Architecture and implementation findings

| Area | Verified finding | Risk | Resolution |
| --- | --- | --- | --- |
| Context | `state.State` embedded `context.Context`; helpers used it as an implicit request context. Forty-six explicit `context.Background` calls also bypassed command cancellation. | Cancellation and ownership were ambiguous; Go recommends passing context explicitly. | Removed context from state, threaded `cmd.Context()` through command/API/completion paths, and added signal-driven `ExecuteContext`. |
| Process lifecycle | `log.Fatal` in `main` and seven constructors skipped defers or terminated the process below the executable boundary. | Owned files could remain open and libraries were not testable. | Constructors return/record errors; `main` owns rendering and exit selection; cleanup errors are joined. |
| Debugging | File diagnostics used mode `0644`, were never closed, and included raw `os.Args`. | Arguments can contain sensitive data and group/world-readable logs are unsafe. | Mode `0600`, explicit close, no arguments, local opt-in JSON `slog` lifecycle records. |
| Configuration | A polymorphic `Read(any)` selected behavior by type, read process arguments and stderr internally, and relied on a mutable exported option map plus init-time mutation. Binding failures were ignored or panicked. | Hidden process coupling, cross-test contamination, nondeterminism, and crashes. | Explicit load methods and injected inputs; immutable per-config option catalogs; all bind/write errors propagate. |
| Persistence | Configuration writes replaced the target directly and did not provide a private atomic-write contract. | Partial writes and permissive modes could expose or corrupt tokens. | Same-directory temporary file, `0600`, full write, sync, close and atomic rename with cleanup-error joining. |
| Command construction | 77 completion registration errors and 72 required/filename marking errors were discarded. | Invalid command trees appeared healthy and failed only during use. | Checked helpers and root-level construction error collection cover all registrations. |
| Completion | Repeated name collection used background contexts, swallowed API failures, cached first errors, and one Primary IP path emitted empty candidates. Certificate commands used Firewall completion in two places. | Incorrect or incomplete shell completion appeared successful. | Shared typed helpers, command contexts, error directives, correct client wiring, and generated mocks. |
| Display lookups | Name rendering performed hidden background API calls and substituted IDs when requests failed. | Failed/canceled requests produced plausible but false-success output. | Context-aware error-returning table fields and name helpers now propagate operational errors. |
| Action polling | Multi-delete associated aggregate action errors imprecisely and could report deletion after an interrupted wait. | False success and loss of per-resource failure attribution. | Typed action failures, complete waits, ownership mapping and explicit incomplete-wait handling. |
| I/O | Commands and SSH reached directly into process stdin/stdout/stderr; table flush errors and several warning writes were ignored. SSH child exit codes were flattened. | Embedding/tests were unreliable and output or child failures disappeared. | Cobra streams, propagated flush/write errors, injected progress writer, and typed exit-code preservation. |
| Mutable test state | Tests assigned `time.Local` directly. | Parallel order dependence and leaked global state. | A serialized cleanup-backed timezone helper scopes every mutation. |
| Availability semantics | `location_available` implied a strict create guarantee, although the API field is only current availability and the full create configuration is authoritative. | Automation could reject valid combinations or assume capacity that was not reserved. | Breaking rename to `location_availability_signal`, supported-location semantics for `location`, and explicit reference documentation. |
| Release security | The release container base was mutable; notarization failure was converted into an empty marker; no SBOM, vulnerability CI job or artifact attestation existed. | Weak provenance and silent publication of incompletely verified artifacts. | Digest-pinned base, fatal notarization, Syft SBOMs, pinned govulncheck, checksums and GitHub attestations. |
| Platform coverage | Unit/race jobs ran only on Ubuntu. | Windows/macOS process, path and signal assumptions could regress. | Platform build/test matrix plus the Linux race job. |
| Documentation | Setup covered only the happy path; architecture, security, availability semantics, current release commands and validation expectations were absent. | Contributor and operator decisions were implicit. | Added architecture, development, security, availability and this decision record; regenerated the manual. |

### TODO and FIXME inventory

The baseline contained exactly two TODO markers and no FIXME markers:

1. `internal/cmd/base/delete.go:150` marked incomplete action-to-resource failure mapping. The typed action-wait and
   delete result implementation resolves it; the marker was removed.
2. `test/e2e/zone_test.go:173` skipped NS/SOA checks because the expected values were dynamic. Stable tokenized
   assertions now cover those records; the marker and skip were removed.

The post-refactor production and test tree contains no TODO or FIXME marker. Future work must be tracked in GitHub or
written as an actionable comment with an issue reference rather than an unowned marker.

### Duplication, complexity, magic values, and hidden state

A deliberately broader supplemental lint profile reported 436 baseline observations: 62 `dupl`, 61 `funlen`, 250
`gochecknoglobals`, 3 `gocognit`, 55 `mnd`, 3 `nestif`, and 2 `nilnil`.

- Most global findings are immutable declarative command/option specifications and constants. Replacing them with
  factories would add allocation and wiring without removing mutable runtime state. The mutable option registry,
  linker setting below `main`, SSH executable global, and raw test timezone state were real findings and were removed.
- Most duplication is generated mocks/manual pages or structurally parallel resource commands. Generic base commands
  are retained as the abstraction boundary. Repeated completion name/label implementations were real duplication and
  are consolidated in `internal/hcapi2/completion.go`.
- The largest production hotspot was `internal/cmd/server/create.go` (494 lines; cognitive complexity 62 in its option
  builder). Other broad functions were output validation (33), configuration loading (34), and the option catalog
  (about 550 lines). Configuration, lifecycle, registration and output responsibilities were cut at explicit
  interfaces. Server creation remains one cohesive mapping of a large upstream API request; splitting it solely to
  satisfy a line limit would obscure validation order. Typed sub-builders remain the preferred direction when new
  options are added.
- The two `nilnil` reports described optional certificate parsing where absence is a valid result, not an error.
- Named domain constants now cover delete parallelism, list pagination and polling/backoff thresholds. Port 22 remains
  the documented SSH protocol default; the shutdown timeout remains a user-visible flag default. API-schema values,
  HTTP status values, address-family widths and test fixture IDs are domain values, not unexplained control constants.
- The pre-refactor scan found 174 explicit `_ =` assignments, 19 multi-result ignores, 25 direct stderr references,
  14 direct stdout references, 9 direct stdin references, 13 `log.Fatal` calls, and 8 panics. Production now has no
  explicit ignored assignment, `log.Fatal`, or panic. Generated mocks and best-effort E2E cleanup retain conventional
  ignored values.
- There are currently 277 same-scope `pflag.Get*` calls that discard the theoretically returned type/registration
  error. Each flag is declared with the same key and type in its owning command, making failure a construction defect
  rather than a user or operational error. Registration is now checked centrally. New commands should bind a typed
  options structure or propagate getters when the declaration and read cross an abstraction boundary; a mechanical
  wrapper with hidden accumulated state was rejected.
- The custom docopt-compatible `util.Validate` is used by roughly 50 command packages and is part of the documented
  CLI usage contract. Cobra's native positional validators do not interpret the repository's `Use` grammar, so this
  is not an unnecessary reimplementation and remains covered by tests.

## 2026 best-practice research

The implementation choices were checked against current primary sources on 2026-08-04:

- Go's [context package](https://pkg.go.dev/context) and
  [Contexts and structs](https://go.dev/blog/context-and-structs) support explicit context parameters and discourage
  storing context in structs. [`signal.NotifyContext`](https://pkg.go.dev/os/signal) is the native cancellation bridge.
- Go's [`log/slog`](https://pkg.go.dev/log/slog) and [structured logging design](https://go.dev/blog/slog) provide the
  supported standard-library diagnostic path; a CLI does not need a custom logging framework.
- Cobra's [command API](https://pkg.go.dev/github.com/spf13/cobra) supports `ExecuteContext`, error-returning handlers,
  checked completion registration and stream injection used here.
- Go's [security guidance](https://go.dev/doc/security/) and
  [`govulncheck` tutorial](https://go.dev/doc/tutorial/govulncheck) recommend reachability-aware vulnerability checks
  in development and CI.
- GitHub's [secure Actions guidance](https://docs.github.com/en/actions/reference/security/secure-use) recommends least
  privilege and immutable action references. GitHub
  [artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)
  provide verifiable build provenance.
- GoReleaser's [SBOM integration](https://goreleaser.com/customization/sbom/) uses Syft for archives and packages; its
  [configuration reference](https://goreleaser.com/customization/) defines the validated release schema.
- OpenTelemetry Go reports stable traces and metrics but beta logs in its
  [language status](https://opentelemetry.io/docs/languages/go/). No outbound exporter was added: this short-lived CLI
  has no telemetry consent, endpoint, sampling or privacy product requirement. Local structured diagnostics solve the
  verified supportability gap without transmitting user behavior. An opt-in OTel exporter should be considered only
  with an explicit product/privacy design.
- Hetzner's [API changelog](https://docs.hetzner.cloud/changelog) states that the server-type location availability
  value describes current availability and is not a guarantee. The supported-location list and the final create
  response have different semantics; [the API reference](https://docs.hetzner.cloud/reference/cloud) remains
  authoritative for request fields.

## Recommendations and disposition

| Recommendation | Disposition |
| --- | --- |
| Make cancellation, cleanup, configuration input and output streams explicit. | Implemented. |
| Fail command construction on invalid registration instead of logging or ignoring it. | Implemented. |
| Preserve resource/action attribution and child exit codes. | Implemented with typed errors. |
| Make sensitive persistence atomic/private and diagnostics local, structured and secret-minimized. | Implemented. |
| Treat availability as an advisory error signal, enumerate supported combinations, and trust the complete create response. | Implemented in CLI semantics and documentation; no billable probe resources are created. |
| Prefer shared/native facilities over hand-written lifecycle, logging, completion and release-error scripts. | Implemented with Go context/signals/slog, Cobra, shared typed helpers, GoReleaser/Syft and GitHub attestations. |
| Add platform, vulnerability and supply-chain verification. | Implemented. |
| Add default remote telemetry. | Rejected pending an explicit privacy/product requirement; local opt-in diagnostics implemented. |
| Replace the docopt-compatible argument validator with Cobra positional validators. | Rejected because it would lose the documented usage grammar and diagnostics. |
| Convert every declarative command global or parallel resource definition into a factory/code generator. | Rejected where state is immutable or code is generated; real mutable globals and real completion duplication were removed. |
| Migrate same-scope flag reads to typed option structures. | Adopt for new/cross-boundary code; incremental migration is appropriate when touching each command because a global compatibility wrapper would introduce hidden state. |

## Breaking changes

This refactor intentionally does not preserve internal Go interfaces. `State`, configuration load/mutation methods,
completion functions, API name helpers, table writes, create printers and root construction now return errors or take
context explicitly. The public CLI behavior is preserved except for the deliberate server-type column rename from
`location_available` to `location_availability_signal`. Debug files are more restrictive and raw arguments are no
longer written.
